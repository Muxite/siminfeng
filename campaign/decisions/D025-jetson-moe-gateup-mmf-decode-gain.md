- Mechanism (J-T3 source analysis + independent review): the fused gate/up+GLU pattern asks the MMVF heuristic ("src0 rows ≤ 512" → vector kernel, 256 threads, F32 activations); standalone NVIDIA bf16 MUL_MAT_ID uses MMF (tensor-core MMA). `GGML_CUDA_J_MMF_IDS=1` declines that fusion on cc 870 when MMF is eligible. nsys (J-P002): gate/up per layer-token 385 µs fused MMVF → 2×131 µs MMF (+GLU kernel); kernel count +3120/64 tok (nothing skipped); GPU time −8.8% under tracing.

- Precision note: MMF rounds F32 activations to bf16 before MMA (mmf.cuh:202-212) — a small numerics change, same class the down-projection already has in the base. Not "bit-exact"; passes the D005 smoke gate and a token-level check.
- Limits: one host, one model/precision, batch 1 decode, MAXN_SUPER with dynamic GPU devfreq (not pinned); only 2 runs per arm (each 5 reps) — effect (≈+10 t/s) ≫ A/A spread (≤0.3 t/s). Unknown on quantized weights (Q8_0/Q4 take MMVQ, different path), on multi-sequence decode, on other cc.
