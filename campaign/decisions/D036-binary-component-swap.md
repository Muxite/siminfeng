# D036 — Engine components are separable at the binary level: swapping one backend .so carries the q8_reuse gain (E1)
Builds q8base-2 (unpatched) and q8reuse-2 (cc/q8_reuse patch) — separate Build CC runs, same commit/toolchain/base digests: of all shared libraries in /app, EXACTLY ONE differs: libggml-cuda.so.0.27.0 (base 14a7d2d8..., reuse f4011d9a...). libllama, libggml-base, libggml-cpu, libggml, libllama-common and all tool impl libs are byte-identical -> builds are reproducible and the q8_reuse component IS one backend library.
Swap: base /app with reuse's libggml-cuda.so bind-mounted, run in the base image: greedy text identical to reference (Q8_0 65894776); llama-bench tg128 alternating OFF/ON/ON/OFF/OFF/ON: OFF 793.8/791.8/793.6, ON 810.0/809.8/808.8 => +2.0%, reproducing D029 (+2.06%) without rebuilding llama (download running concurrently; spreads still <0.3%).
Implication for the factory: version components at their engine layer — model artifact (GGUF+imatrix+recipe), runtime config (flags), backend binary (libggml-cuda / libggml-cpu), scheduler/core (libggml-base), model graph/loader (libllama). A backend-only component can be released and A/B-tested as a single .so against a fixed engine, if the ggml ABI version matches (0.27.0 here). Not shown: swaps across different ggml versions, or of components touching libllama (graph/loader), which need ABI/symbol checks (T-COMP).
