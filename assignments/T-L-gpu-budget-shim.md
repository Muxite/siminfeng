# Assignment T-L (parent: campaign c1 / memory-restriction; orchestrator = Claude)
Goal: a campaign-local, deterministic way to RESTRICT the GPU memory a process may use, so a small model behaves like a "too-big" model (we simulate fitting a 500 GB MoE into 128 GB by giving Granite a budget scaled by the same ratio: ~0.26 x 2.67 GB ~= 700 MiB). No host-wide driver changes, no MPS daemon, no privileged flags.
Design to implement: `libgpubudget.so`, an LD_PRELOAD interposer written in C (C99/C++ ok), compiled in container campaign/cuda-tools:c1 (nvcc 12.8, g++, cmake; you cannot run Docker — write code + build script + test; the orchestrator compiles and runs them):
 - env GPU_BUDGET_MIB=<n> (hard cap on device allocations made through the interposed APIs); GPU_BUDGET_LOG=<path> optional JSONL of events (alloc/free/deny with sizes, running total, peak) flushed on each deny and at exit (atexit + destructor).
 - Interpose runtime API: cudaMalloc, cudaMallocAsync, cudaMallocPitch, cudaMalloc3D, cudaMallocManaged (counted ONLY when it is later prefetched/resident? keep simple: count requested size but offer GPU_BUDGET_COUNT_MANAGED=0|1, default 1), cudaFree, cudaFreeAsync; driver API cuMemAlloc_v2, cuMemAllocAsync, cuMemFree_v2, cuMemCreate, cuMemRelease (VMM) if feasible; report honestly which APIs are NOT covered. On exceeding the budget: do not allocate, return cudaErrorMemoryAllocation / CUDA_ERROR_OUT_OF_MEMORY.
 - Interpose cudaMemGetInfo / cuMemGetInfo_v2 to report total = budget and free = budget - used, so engines that size themselves from free memory (llama.cpp's --fit logic, ggml_backend_dev_memory) adapt to the restriction.
 - Thread-safe (mutex), tracks allocation sizes by pointer (hash map), tolerant of frees of unknown pointers, counts bytes only for successful allocations. Document the CUDA context/cuBLAS workspace overhead (~300 MiB) is NOT counted when created internally by libcuda/cudart and say how a caller can account for it (e.g. GPU_BUDGET_RESERVE_MIB).
 - Works with llama.cpp built by the Build CC: llama.cpp can use VMM pools (cuMemCreate); recommend/verify env GGML_CUDA_NO_VMM=1 so allocations flow through cudaMalloc, and document that interposition requires dynamic linking of libcudart (our image links libggml-cuda.so dynamically against libcudart.so.12).
