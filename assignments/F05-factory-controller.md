## Build
1. `jiuwenswarm/factory/controller.py`:
   - `init_task(task_file) -> task_id`: task JSON (`objective, constraints, allowed_effects (grants), target, budget {max_turns, wall_clock_s}, contract_id, initial_run_config, component_cc, source {workspace subpath, pre_integration_commit}`) → `Store.create_task`. The **operator** writes this file; it may contain a clearly labeled controlled-invalid setting (field `operator_labels`), which the controller passes to the agent verbatim as part of the objective; the controller never fixes it.
   - `configure_agent(task)`: like `demo/run_agent.configure` but: `--ccs jiuwenswarm/factory/ccs`, `--store FACTORY_HOME/ccstore`, `--workspace FACTORY_HOME/agent-workspace`, grants = task `allowed_effects` ∩ operator CLI `--grant` list (never wider); MCP server env must carry `FACTORY_HOME`, `FACTORY_TASK_ID`, `FACTORY_WORKSPACE`, `DOCKER_CMD_PREFIX=sg docker -c`, PATH with `/usr/local/cuda/bin` (add them to `[mcp_servers.cc.env]`); data dir `FACTORY_HOME/agent-data`; transcript `FACTORY_HOME/sessions/<task_id>.jsonl` (append; scrub like run_agent; include tool calls/results).
   - `run(task_id)` loop (host enforces; **agent decides**):
     a. Turn message = short, ID-based: task id, objective (first turn only), current decision rev, evidence cursor, list of attempt ids + states that changed since last turn, remaining budget. **No producer prose / no previous transcript summary** — the agent must use `factory.evidence.query/read` to learn details.
     b. Standing agent instructions (put in `jiuwenswarm/factory/AGENT.md`, sent on the first turn): the cycle — query evidence and record which ids you considered → publish a decision (observations, hypothesis, uncertainty, next bounded action, expected evidence, budget, stop condition, `reason_for_change` citing evidence ids, `expected_rev`) → act via CCs or coding tools in the owned checkout (read `factory.engine_component` and `factory.integration_skill` materials first) → ingest/inspect receipts → decide again. Long work: `submit` then **end your turn** saying which attempt you wait on. Terminal decisions: action.type ∈ `accept | report_inconclusive | stop_missing_prerequisite` with evidence ids. Never edit contracts; never widen grants; failed receipts are failures.
     c. After each turn: read the latest decision from the store. If terminal → finish. Else if any attempt is `queued|running|cancel_requested` → wait **without model calls** (poll `Jobs.status` every 15 s; persist), then next turn. Else → next turn.
     d. Budget: max_turns and wall-clock enforced by the host; exhaustion → task outcome `partial` with pending attempts/questions listed; never a pass.
     e. Turn result validation: if the agent ended a turn without publishing a new decision revision, the next turn message says so (host-observed fact), counted against budget.
   - `resume(task_id)`: reconnect after controller restart: same `session_id` (= task_id) → same Codex thread; reconcile attempts via `Jobs.status` first.
   - `status(task_id)` (progress view, plain text + `--json`): objective, latest decision rev + action + reason_for_change, active jobs, artifacts (id, media type, size), evaluations, readiness flags, budget used.
2. Native entrypoint: `jiuwenswarm factory {init,run,resume,status,show,cancel}` — add a `factory` subcommand to `jiuwenswarm/channels/cli/main.py` (minimal, lazy import of `jiuwenswarm.factory.cli`) **and** a `[project.scripts] jiuwenswarm-factory = "jiuwenswarm.factory.cli:main"` entry; both call the same `jiuwenswarm/factory/cli.py`. `cancel` = record cancel intent for all active attempts via `Jobs.cancel`. The legacy-config guard must still run first.
3. Login handling: `jiuwenswarm factory login|auth-status` reusing `get_service().login()/status()` under the factory data dir (the operator already has `~/.codex/auth.json`; follow run_agent's documented copy path; never print tokens).
