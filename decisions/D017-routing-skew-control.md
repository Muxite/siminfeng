# D017 — Is Granite routing skew real? (answering claim-register P12; ProMoE says modern MoEs have near-uniform expert access)
Evidence: experiments/routing/{control_uniform,prose,code,chat}.json (trace_replay), artifacts/traces/out/*.jsonl. Control = SYNTHETIC uniform-random top-8 trace (24 layers x 2000 decode tokens), labelled.
- Control hit rate (LRU and LFU) = slots/32 exactly (12.4, 24.9, 37.4, 49.9, 74.9%): simulator has no bias.
- Real Granite decode traces (cold start, 96-160 decode tokens, single sequence): LRU at 8 slots prose 49% / code 36% / chat 45% (LFU up to 49%) vs 25% control; at 16 slots 70-81% vs 50%; at 24 slots 88-94% vs 75%. => within-request skew/temporal locality is REAL for Granite.
- Mild: normalised usage entropy 0.88-0.92 (1.0 = uniform). Pooling the three workloads raises it to 0.936; top-8 hottest experts overlap 0.47 between workloads (random 0.25). => partially shared hot set, weaker when pooled; consistent in direction with MoE-Infinity (skew within request, weaker pooled) and ProMoE (near-uniform at scale).
Limits: 3 workloads, 1 sequence each, 96-160 decode tokens (cold-start dominated), prefill excluded from decode stats, Granite != target. Does NOT show the target model's routing is skewed. Needed before sizing any hot-expert cache: target-model traces across domains, long decodes, pooled multi-request.
Effect on D014: the prediction stands only as "if the target routes like Granite"; it must be re-derived from target traces. Claim P12 status: partially supported locally for Granite (within-request), pooled-uniformity question open.
