## Build (new files only, under `jiuwenswarm/factory/` and `tests/factory/`)
1. `jobs.py` — `class Jobs(store, jobq_bin=Path('/home/muk/projects/siminfeng/bin/jobq'), jobq_dir=None)`:
   - `submit(task_id, kind, request: dict, idem_key: str, job_class: 'build'|'gpu'|'cpu', argv, timeout_s, env_extra) -> attempt`. Fingerprint = sha256 of canonical JSON of `{kind, request, argv, job_class, timeout_s}`. Persist the attempt row (state `queued`, fingerprint, idem_key) **before** calling `jobq submit`; then store the jobq id. Same `(task_id, idem_key)` + same fingerprint → return the existing attempt, no new jobq job. Same key + different fingerprint → `KeyConflict`. Always prepend `/usr/local/cuda/bin` to PATH in the submit env and set `DOCKER_CMD_PREFIX='sg docker -c'`.
   - `status(attempt_id)`: read jobq job JSON, map to `queued|running|succeeded|failed|cancel_requested|cancelled|unknown` (jobq `timeout`/`skipped_dep_failed` → `failed` with detail; missing jobq record → `unknown`). Persist transitions into attempt `history` with timestamps. Never infer termination from a caller timeout.
   - `cancel(attempt_id)`: record `cancel_requested` (intent) → `jobq cancel` (action) → `status` until jobq terminal (observed) → `cancelled`; record cleanup_state from jobq/owned container reaping.
   - `retry(attempt_id, new_idem_key)`: only after the prior attempt is terminal (reconcile first), creates a new attempt linked via `history.retry_of`.
   - `result(attempt_id)` returns state + result refs; a non-succeeded attempt never yields reusable output.
   - Reconnect = construct `Jobs` again and call `status`; nothing lives in the caller process.
2. `build_job.py` — the Builder **worker** executed by jobq (`python -m jiuwenswarm.factory.build_job --task T --attempt A --request request.json`):
   - **dependency preparation** step → `prep.json`: tool versions (`nvcc --version`, gcc, cmake, ninja, docker buildx), `nv_tegra_release`, `nvidia-jetpack` version, disk free (fail if < 8 GiB), ccache stats, base image present by digest (`docker image inspect <ref@digest>`: present → `cache_hit: true`; absent → `docker pull <ref@digest>` and `cache_hit: false`; never pull by tag). Missing toolchain → prep fails with structured error `{"code":"TOOLCHAIN_MISSING","tool":"nvcc","path":...}` and the build is not started.
   - **build**: run `build_engine.py --target jetson-orin --source <request.source.path> --commit <request.source.commit> --tag <request.tag> --out <unique attempt dir>` (+`--patch` if given). Never reuse an existing out dir.
   - **ingest** into the store (it is a host component, allowed to write): artifacts for prep.json, build-record.json, build stdout/stderr (bounded tails + full as artifact), and one observation `{kind: build_result, values: {status, failure_stage, image_id, tag, source_commit, source_tree, patch_sha256, toolchain, base_images, build_wall_seconds, cache_hit}}`. Linked receipts: request fingerprint ↔ prep ↔ build record ↔ image id.
3. `builder.py` — high-level `submit(task_id, request, idem_key)`, `status`, `cancel`, `result` used by the api: validates request (`target` must be `jetson-orin`; source path must be a git repo whose HEAD == commit and clean; tag namespace `factory/llamacpp:*`), computes argv for `build_job`, calls `Jobs.submit(job_class='build', timeout_s=request.deadline_s or 5400)`. Reuse rule: a previous **succeeded** attempt with identical fingerprint is returned (no rebuild); anything differing (commit, patch, tag, target, toolchain-relevant env) cannot reuse it.
4. Extend `api.py` dispatch: `builder.submit|status|cancel|result` (submit returns `{attempt_id, state, jobq_id}` immediately).
