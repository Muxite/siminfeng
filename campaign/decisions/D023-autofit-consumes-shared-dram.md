# D023 — llama.cpp auto-fit context consumes Jetson shared DRAM; pin -c in test policy (2026-11-10, jetson-arm)
- Observation: lab test `gen_smoke` (no -c; 24 tokens) on jetson-c1 picked `n_ctx = 45568` (stderr of lab/jobs/job-4433960e61/att-1). Shared-DRAM high-water 6568 MiB vs 1634 MiB baseline (tegrastats RAM used, scope system-shared-dram) on a 7607 MiB device; earlier gen_smoke 5647 MiB. 
- Cause (source-supported): the fit logic sizes context from device free memory (cudaMemGetInfo / ggml_backend_cuda_get_available_uma_memory — the log prints "final available_memory_kb"); on Tegra this is system-available DRAM, so engine residency competes with OS/controller/agent headroom. On x86 the same default only consumes VRAM.
- Decision: Jetson test policies pin context explicitly. Added `lab/tests/jetson.json` (`gen_smoke_c2k`, `ppl2` unchanged since it already passes -c 512). x86's `lab/tests/quality.json` untouched (changing it would change x86 test identity) — x86 owner to decide whether gen_smoke should pin -c too, since its result also depends on free VRAM.
- Applicability rule for Manager/test CCs: on shared-memory platforms any engine default derived from "free device memory" is a host-memory policy; admission must declare it (memory.domain: shared-dram) and the test policy must fix it. A cudaMemGetInfo-interposing budget (x86 cc/gpu_budget, T-L) is the natural cap here — untested on Jetson.
- Also fixed: J-T4b treated J-T4-era admission records without a hash as "mismatch"; now "recorded-unhashed (pre-J-T4b)" and still re-checked (old rejected job still refused).
