## Deliverables
1. cc/acc/datasets.py: normalized JSONL schema {id, source, question, choices: [..] | null, answer (letter or string), meta}. Fetchers via the HF datasets-server rows API (`https://datasets-server.huggingface.co/rows?dataset=D&config=C&split=S&offset=O&length<=100`, JSON, stdlib urllib) for: MMLU-Pro (TIGER-Lab/MMLU-Pro, test), GPQA-Diamond if public mirror exists (else skip with message), ARC-Challenge (allenai/ai2_arc, ARC-Challenge, test), GSM8K (openai/gsm8k, main, test). Deterministic subset selection: seeded (seed recorded) stratified by category where available; write data to ~/models/campaign/data/acc/<name>-<n>-s<seed>.jsonl + a .meta.json with source URL, row offsets, sha256. Fetch code must be runnable by the lead (you have no network; unit-test the parsing on a tiny captured-shape sample you construct from the documented API response shape and label it SHAPE-ONLY in the test name).
2. cc/acc/server.py: start llama-server in docker (reuse om_run conventions: `${DOCKER_CMD_PREFIX}`, --runtime nvidia, NVIDIA_VISIBLE_DEVICES=all, model dir ro mount, `--network host` bound to 127.0.0.1 on a free port, unique container name, always killed in finally/atexit), health wait, telemetry via cc/resource_observe running alongside (same as om_run), watchdog limits as om_run. Pass-through engine argv and env (so expert_fill/pregate env works).
3. cc/acc/mcq.py: for MCQ sets, chat request with model's own template, non-thinking where the template supports it (`chat_template_kwargs: {enable_thinking: false}`; record which), prompt format fixed + recorded (question, lettered choices, "Answer with the letter only."), max_tokens 1, temperature 0, top_logprobs 20: prediction = argmax over choice letters among returned top logprobs (letters with/without leading space); record whether the argmax letter was found in top-k (else count `no_letter`). Output per-item JSONL + summary.json {n, correct, acc, wilson95_lo/hi, no_letter, mean_ms_per_item, prompt_tokens_total}. Resume support: skip ids already in the output file.
4. cc/acc/gen.py: GSM8K-style generation: max_tokens configurable (default 384), temperature 0, extract last number / "The answer is N"; exact numeric match; same summary schema + mean decode tok/s from server timings.
5. cc/acc/kld.py: wrap llama-perplexity: (a) `--kl-divergence-base` save from a reference model, (b) candidate `--kl-divergence` run; parse to JSON {ppl, mean_kld, kld_p99, same_top_p, rms_dp, n_chunks, n_ctx} from the fixture format. Text: ~/models/campaign/data/wikitext/wikitext-2-raw (wiki.test.raw); fixed -c 512 --chunks configurable.
6. cc/acc/compare.py: two summaries → difference in accuracy with a paired McNemar exact test on per-item correctness (stdlib) + Wilson CIs; markdown table.
7. cc/acc/README.md (how to run each, costs per item measured later), tests cc/acc/test_acc.py (parsers from fixtures, letter-argmax edge cases, Wilson, McNemar exact against hand-checkable small tables, resume logic, docker argv construction incl. kill-in-finally — mock subprocess).
8. jobq integration: every on-device run is a CLI that the lead submits as `bin/jobq submit --class gpu ...`; document the exact command lines in README.
