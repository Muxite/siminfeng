## Deliverables (python3 stdlib only; package dir cc/abrun/)
1. `cc/abrun/run_summary.py DIR [DIR...] [--json]` -> per run dir a summary dict, also written to DIR/summary.json:
   status (from result.json), wall_s, prompt_tps / eval_tps (last `common_perf_print` prompt eval / eval lines in stderr; also llama-bench `-o json` stdout: pp/tg avg_ts and samples_ts, steady = mean of samples[1:]), load_s, nvme_gib (max-min of telemetry metric `device_read`, KiB units), avg_kib_per_io (device_read delta / device_read_ios delta), nvme_gib_per_token (when eval tokens parsed), mem_available_min_mib, swap max, gpu_freq median, output_sha (sha256 of stdout.txt, first 12 hex), and `switch_lines`: stderr lines matching any regex given via `--switch-regex`. Missing metrics -> null + reason string, never crash.
2. `cc/abrun/gate.py`: given labelled summaries (arm -> list of runs, in execution order) compute per-arm mean of the chosen metric, the B/A ratio, A/A gap (if an arm has >= 2 runs: (max-min)/mean of that arm; take the max over arms), drift (first-half vs second-half of the base arm), and verdict per the rule: `improved` if ratio-1 > max(0.03, 2*aa_gap, 2*drift); `regressed` if 1-ratio > same threshold; else `null`. Also an output-class check: `identical` (all output_sha equal across arms), `differs` (list which). Verdict object is JSON, includes every input number.
3. `cc/abrun/preflight.py`: given image + tool + argv, obtain `/app/TOOL --help` text (via a pluggable runner; real runner = `$DOCKER_CMD_PREFIX docker run --rm --runtime nvidia --entrypoint /app/TOOL IMAGE --help`, cached under lab/preflight/<sha of image ref + tool>.txt) and reject any `-x`/`--xx` flag in argv not present in the help text. Exit nonzero with the offending flags listed.
4. `cc/abrun/abrun.py SPEC.json [--dry-run] [--submit]`: spec schema (document it in README):
   `{"id","outdir_base","runner":"om_run","tool","argv":[...],"switch_regex":[...],"metric":"eval_tps","arms":{"base":{"image":..,"env":{}},"pf":{"image":..,"env":{"LLAMA_EXPERT_PREFETCH":"1"},"expect_switch":true}},"order":"ABBA"|"ABCCBA"|"explicit","explicit_order":[...],"rounds":1}`.
   Generates a counterbalanced order (ABBA for 2 arms, ABCCBA for 3, mirrored for N), runs preflight once per (image,tool), then each run via `cc/om_run/om_run.sh OUTDIR IMAGE "-e K=V ..." TOOL ARGV` wrapped in `bin/run_op --agent abrun --task <id>`; after each run writes summary.json; if an arm has `expect_switch:true` and its run has zero `switch_lines`, or a base arm HAS switch lines, mark the experiment INVALID (switch inert / leaked) and stop. Final: `OUTDIR/verdict.json` + `OUTDIR/REPORT.md` (table of runs in order, per-arm means, gate verdict, output class).
   `--dry-run` prints the planned order and commands without running anything. `--submit` (optional, only if `bin/jobq` exists) submits the whole experiment as one `gpu` class job instead of running inline.
