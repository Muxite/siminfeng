# SPEC1: speculative verify-window expert-union replay

CPU-only offline simulation; no GPU, Docker, builds, network, or commits.

## Findings

These traces do not predict a material disk-bound speculative gain. The best W>1 case in the entire sweep is optimistic LRU, code, 650 slots, a=0.9, W=2: **1.0011x**, effectively break-even. The best optimistic Belady case is 0.9555x; the best pessimistic LRU/Belady cases are 0.9046x/0.8817x. At a=0.7 and 1300 slots, optimistic LRU W=4 gives 0.618–0.631x across workloads, before any drafting cost. Thus the x86 acceptance gains do not establish a Jetson benefit under these replay assumptions. Wider unions increase traffic and can change cache residency; reuse alone does not guarantee lower bytes per emitted token. The hypothetical compute cap affects 18 of the 864 scenarios.

## Model and scope

W is the total number of verify positions, including one guaranteed output position (W-1 draft positions). Expected emitted tokens per full window are E(W,a) = sum(a**j for j=0..W-1) = (1-a**W)/(1-a); at a=1 the limit is W. This follows the assignment's explicit formula; describing W as W drafts plus a bonus would instead require W+1 terms. Partial final windows use their actual length in both routing and E. Windows never cross sequence boundaries or gaps. Only explicitly marked decode rows are replayed, with cold global caches and no prefill warming. Every union is replayed layer by layer, with experts in first-observed order, through existing LRU and Belady (future-reading oracle with bypass) policies. These are sequential demand lookups, not an atomic pinned verify working set. Caches persist across windows. Each slot is 1,900,544 bytes (589,824 + 589,824 + 720,896).

Optimistic: union actually realized consecutive tokens. Rejected drafts would route differently, so this is an optimistic proxy, not measured speculative decoding. Pessimistic: sample a prefix rejection using per-position acceptance a (first verify position is guaranteed); after the first rejection, add an independent uniformly sampled distinct top-8 per layer for each remaining position, retaining the realized union. This intentionally adds rather than replaces traffic. It is a conservative scenario, not a rigorous bound on every possible draft router. One reproducible random realization per trace/W/a uses seed 20261110; there are no confidence intervals. Expected output remains the analytic geometric expectation, not the sampled prefix length. The W=1 variants coincide.

Disk t/s = 570 MiB/s / miss bytes per emitted token. Speedup compares the same workload, policy, capacity and acceptance against W=1. The hypothetical compute cap assumes at most 6 verify steps/s: total time = max(total disk time, number of windows / 6); capped t/s = expected output / total time. This assumes ideal disk/compute overlap; additive costs would be slower. The cap is hypothetical, not a Jetson measurement. Draft computation, MTP-head memory (which could shrink the cache), attention/KV/shared-expert costs, page granularity/readahead, and capture timing overhead are excluded. Distinct counts are averaged equally over layers and windows, including partial windows. JSON also contains individual layer means, lengths, totals, input paths and diagnostics. Trace metadata omits a model SHA.

The local research/x86-c2-digest.md reports T-SPECM ~19 experts/layer for four positions, MTP chat acceptance 64–70%, and cache+MTP incremental chat gain only ~6.5% on x86; these motivate the sweep, not calibration or transferable measured Jetson throughput. At a=.65, E(4,a)=2.347; a ~19/8 union expansion can therefore erase the gain before cache effects.
