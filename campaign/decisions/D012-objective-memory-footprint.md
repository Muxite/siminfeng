# D012 — Objective reframed: reduce GPU memory at similar accuracy and acceptable tokens/s (user, mid-session)
User: "our goal is to reduce memory usage on the GPU while having similar accuracy and acceptable tokens/s ... real challenge: super big MoE (500 GB weights into 128 GB memory + 4 TB SSD) ... target system is unified memory, we are discrete memory ... agent swarm; opus allowed for hairy tasks; codex for small tasks; may ask gpt6 astra via codex."
Consequences:
- Primary metric = GPU memory footprint (weights + KV + compute buffers; peak from nvidia-smi, cross-checked with llama.cpp's own buffer report); secondary = quality (paired KL / top-1 vs BF16, PPL) and decode/prefill t/s. Report a Pareto frontier, not a single "win". The earlier speed screens (D008-D011) are kept; speed-only candidate C1 (q8 activation reuse) is DEMOTED to a component/build-CC integration exercise.
- Scale analogy: 500 GB -> 128 GB is ~3.9:1. Granite BF16 = 2.67 GB => scaled GPU budget ~0.7 GB. Experiments report whether a configuration fits under the scaled budget. Labelled an ANALOGY, not full-scale evidence.
- Discrete vs unified memory: TRANSFERS: accuracy/KL, routing statistics, expert-usage skew, cache hit-rate-vs-capacity curves (trace replay), byte accounting, quantization effects. DOES NOT TRANSFER: PCIe copy cost/overlap, pinned-host staging, GPU-vs-CPU placement timing (on unified memory a "CPU expert" and a "GPU expert" share DRAM; the cost model is bandwidth contention + page residency vs SSD). Every result states which class it belongs to.
- SSD tier can be emulated campaign-locally (no host-wide cache flush): run with a container memory limit smaller than the mmap'd weights so page-cache eviction forces SSD re-reads.
- Method families to attempt (cheap screens first): representation (uniform + mixed per-tensor, experts lower-bit vs attention higher-bit), expert placement (--n-cpu-moe / -ot), KV cache quantization/context, trace-driven residency sizing (routing_trace + replay), SSD-tier emulation via cgroup memory limit. Strata-style adaptive slot caches are studied from source (map) and simulated via trace replay; llama.cpp has no adaptive expert cache.
