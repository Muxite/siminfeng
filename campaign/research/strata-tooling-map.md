## 0. What Strata is (context for every verdict)
Product-level inference engine (own C++/CUDA/HIP/SYCL/Metal runtime in `src/`, Python server in `serve/`, CLI in `strata_cli/` + `strata_control/`, Tauri/Node desktop app). It runs Qwen3.8-Flash-Next (48 layers x 512 experts = 24,576 experts) and DeepSeek V4.1-Flash (15,744 experts) with a GPU expert cache + all experts in pinned RAM + CPU experts (`docs/HOW_IT_WORKS.md`). It is NOT llama.cpp-based at the top level (only the vendored `third_party/strata-ggml` for IQ-quant kernels). So engine code does not transfer to us; the tooling and methods do.

## 2. Methodology comparison (from `docs/BENCHMARK_PROTOCOL.md`, `COMMUNITY_BENCHMARKS.md`, `DGX_SPARK_LINUX.md`, `autotune.py`)
Strata rules worth noting:
- Frozen fixtures with committed `MANIFEST.sha256`; corpus sha is `protocol.corpus_sha256`; `.gitattributes -text` so line endings never change bytes; runner refuses on one byte difference; rebuilds byte-for-byte via `tools/build_standard_corpus.py`.
- Any change to prompts/order/caps/scoring requires a NEW protocol ID; schema changes use a separate version. Draft protocol is labelled "draft" until a two-hardware pilot.
- Two tracks never merged: `default` (setup-generated) vs `custom`; "claimed improvement requires a separate same-machine baseline".
- Metrics defined by engine counters only (`read_tokens/prompt_s`, `decode_tokens/decode_s`); cached tokens never in numerator; client clocks only for TTFT/total; never divide output tokens by wall time and call it decode speed; keep API token count and engine count separately and explain mismatch.
- Unexpected prompt-cache reuse check: `cached_tokens <= max_shared_prefix_tokens + 8` else exclude from speed summary, mark run nonconforming; restart engine between runs.
- null with a JSON-Pointer `missing` reason for every unavailable value; no 0/"N/A"/NaN. Status `complete|partial|nonconforming`. Medians/min/max/n per case, never pooled across sizes/quants; exclusions listed with reasons; "never hide early EOS, failures, slow samples"; partial keeps real n.
- Capped outputs counted (`Capped` column): 35/36 long requests hit the cap while still reasoning, so decode TPS is "to-cap" time.
- Sanity checks are exact-match / strict-JSON with no LLM judge; quality never merged with speed.
- Hardware record: unified memory flagged `memory_kind: shared`, power limit null with reason, `background_workloads` listed, loopback only, remote = nonconforming.
- DGX doc: ABBA block order, 4 samples/cell, medians, "figures move a few percent between sessions"; `STRATA_SM121_PERF=0` A/B switch to isolate a table; identical-logits check to prove a diff is the switch, not noise.
- Autotune: gain must beat 2x A/A gap and 2x drift; early drop after 1 round at -5%; "a gain the noise can explain is not a gain".
- What Strata does NOT do (we do): no clock/governor capture ("no clock capture" is admitted in COMMUNITY_BENCHMARKS L58), no formal A/A run, no ub=1 KL gating (its KL uses decode windows and a fixed config), no per-sample first-iteration-ramp exclusion.

Concrete rules for us to add:
1. Record `protocol_id` + corpus sha256 in every result; any change to prompts/caps/seeds/order = new id; `-text` gitattribute on fixtures.
2. Result schema: unavailable = null + pointer-keyed reason; status `complete|partial|nonconforming`; `n` kept honest.
3. Prompt-cache-reuse assertion (`cached_tokens` vs allowed shared prefix) on every serve-style run; restart between runs.
4. Report "capped / early-EOS" counts next to every decode rate; forbid pooling across context depths.
5. Adopt Strata's accept rule in `perf_summary`: median of per-round ratios >= +3% and > 2x A/A gap and > 2x drift, in all rounds (>=4 of 5 in confirm), plus <=2% regression on the other phase (pp when tuning tg).
6. Classify every optimisation as `exact` (byte-identical greedy output) / `numerically different` / `lossy`; only `exact` auto-accepted (our D027 "identical outputs" is that class).
7. Tag runs with the machine "noise state": record A/A gap and drift beside each A/B (we have A/A; make it a stored field).
8. Keep default vs custom tracks and a same-machine baseline for any claim.
9. Add a cell grid (prompt length x cached fraction x gen) and ABBA ordering for depth sweeps, which also addresses our Jetson first-sample clock-ramp artefact (J-E002).
10. For unified memory, adopt `memory_kind: shared` + the "pinned RAM costs 2x in a shared pool" kind of measured constant (`strata_control/uma_pool.py`: pool demand = fixed + cache slots x slot size + 2 x RAM-held experts; measured on 128 GB Strix Halo, hang with 41 s silent exit when overcommitted). Test whether our Jetson mmap/pinned path doubles residency (J-E003 saw +2.5 vs +1.8 GB cached).

## 3. Build / dependency management
- Python: `requirements.txt` exact pins with python_version markers and security-note comments (Pillow GHSA); `requirements-build.txt` (cmake, ninja pip wheels), `requirements-dev.txt`, `requirements-monitor.txt`; per-platform hashes-style lock files `packaging/locks/runtime-{linux-x86_64,linux-aarch64,darwin-arm64,windows-x86_64}-cp312.txt` produced by `packaging/lock_wheels.py`.
- Toolchain: `flake.nix` pins nixpkgs-unstable (flake.lock), CUDA 13.0 (`cudaPackages_13_0`) because 13.2.0/13.2.1 miscompile sm_120; x86_64-linux only; cmake/ninja from nix, not pip. `spark/build_engine.sh` warns on those toolkit versions. NOTE for us: CUDA 12.8/sm_120 is not the version they pin; their miscompile warning applies to 13.2.x, not 12.8, but check our toolkit before any 13.x move.
- CMake: `CMakePresets.json` v5 (new since ffa80d73): `cpu-check` (no GPU/no network), `cpu-check-native`, `cuda-compile` (`CMAKE_CUDA_ARCHITECTURES "86-real;89-real;89-virtual"`), `hip-compile`; same flags as the release scripts so CI compile-only builds equal release builds. Vendored ggml (`third_party/strata-ggml`, `tools/check_vendored.py`) with `-DSTRATA_GGML_DIR` override.
- Docker: `Dockerfile`, `docker/` (entrypoint, healthcheck, smoke-test, compose per vendor), `.github/workflows/docker-images.yml`; the engine is fetched as a signed feed package (`packaging/feed_tool.py`, `signing.py`, `update_keys.json`), not built in the image.
- Packaging: per-platform build scripts, `package_engine.py`, signed feed with `min_driver`, `collect_libs.py`/`binary_deps.py` bundle CUDA libs.
- aarch64/Jetson/sm_87: aarch64 YES but only DGX Spark: `packaging/build_cuda_linux_aarch64.sh` + `spark/build_engine.sh` (default `ARCHS=121`, CUDA 13.0, glibc >= 2.39, driver >= 580.65, built on the device itself, "no older arm64 chroot"). `grep` for sm_87/Jetson/Orin in the repo (excluding third_party) finds no hit; sm_87 is not a target, CPU kernels for Q2_0/Gyro are x86-only. `CMakePresets` omit aarch64.
- Fit to our two targets: (a) reproducible pip-style pins + per-platform lock files are ADOPT for Python helpers (`cc/`, `lab/`); (b) CMake preset names `*-compile` = what our Build CC `cuda_compile_check` does, copy the "same flags as release" discipline; (c) nix flake is PATTERN only: x86 only and JetPack 6.2 cannot be nix-built (L4T driver stack), so for the Jetson keep host-native build + ccache; for amd64 CUDA 12.8 sm_120 a flake could pin nvcc/gcc, but our Docker/Buildx digest pinning already gives the same and works on both targets, so do not add nix; (d) record toolkit-version blacklist (miscompile warning) in the Build CC.

## 5. Gaps neither project covers (goal: MoE ~4x device memory, unified memory + SSD, acceptable quality and t/s)
Strata does not either: its largest case (DeepSeek V4.1 2-bit) is 257 GB on a 128 GB Spark and still keeps experts in RAM/mmap plus CPU lane; the 4x oversubscription with SSD in the expert path is only touched via the n-gram table on SSD (NVFP4 locked-in-RAM measured 26 vs 39 tok/s decode). Gaps:
1. SSD expert streaming with prefetch/readahead and a cache hierarchy (VRAM/pinned/pagecache/SSD) on unified memory: no I/O model (queue depth, O_DIRECT vs mmap, NVMe bandwidth on Orin/Spark), no cold-start vs steady-state split. Strata has `tests/platform/direct_file_async.cpp`, `io_priority_test.cpp` and `serve/cache_drop.py` (page-cache give-back) only as small hooks.
2. Router-aware prefetch (predict next-layer experts from the current routing) and its accuracy measurement on traces; replay tools here only cover reactive eviction.
3. Quality under on-demand quantization/mixed precision and under expert skipping/substitution (Strata has `STRATA_ROUTE_TAIL_SKIP`, KVA approximations, but no joint t/s vs KL Pareto per memory budget); our `cc/memory_pareto` is the nearest.
4. A trace corpus for a LARGE real MoE (routing skew at 256-512 experts, top-8+); we only have Granite 1B/400M-active (mild skew, D017). Strata's skew claims come from its own model.
5. Memory-limited execution test: hard enforcement of a device-memory cap on shared DRAM (our `gpu_budget` shim is untested on Jetson; Strata sizes from `MemAvailable - 6 GiB` heuristics, `DS4_UMA_HEADROOM_GIB`).
6. Thermal/clock/power state as a first-class covariate (neither records governor + clocks per sample; ours has nvpmodel/devfreq in summary but not per-sample).
7. Cost model that predicts t/s for (hit rate, miss cost, SSD bandwidth, overlap) validated end-to-end; our D019 says the overlap bound is not supported.
8. Crash/soak behaviour of a swap-heavy run (OOM killer / zram / page-cache thrash cliffs, our D015) with an automated guard that aborts before the host stalls.
