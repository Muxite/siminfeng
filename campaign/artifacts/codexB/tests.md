## How to interpret and run the inventory

Commands below are **future recipes**, to use in an authorized writable copy with dependencies already present. They were not run against the read-only input. Some tests create files or subprocesses and some explicitly download/build real packages; do not run the whole tree under this assignment's write/network restrictions.

- **P(path)** means `python -m pytest -q -p no:cacheprovider path` from the source root. This collects pytest functions and unittest classes alike. `tools/test_setup_*.py` generally also run as `python tools/test_setup_NAME.py`; repository guidance documents this at `AGENTS.md:81-84`. Dependencies include pytest and, by suite, Textual, NumPy, gguf-py, cryptography, platform tools or local executables. A skipped optional dependency is not a pass of its guarded behavior.
- **N(target)** means run the built executable `B/target` (or the corresponding configured subdirectory / `.exe` on Windows), where **B** is a separate build tree. For registered tests, prefer `ctest --test-dir B --output-on-failure -R '^target$'` to preserve CMake's environment and skip settings. A target name is not necessarily a registered CTest name: unregistered developer targets run directly. Target associations below come from `CMakeLists.txt` `add_executable` declarations; backend/feature gates still apply.
- A future CUDA test build normally uses an existing configured CUDA tree with `STRATA_BUILD_TESTS=ON`; build the selected target rather than the default `all`. Feature targets additionally need native-expert, MMQ, K-quant, conversation or backend options as indicated in `CMakeLists.txt`. **Runtime CPU-only does not always mean the target configures/links without a CUDA SDK.** Several CPU tests are declared inside the engine/CUDA block; wrapped-device tests still link that engine.
- **CPU** means no real GPU/model is needed by the default test. **CUDA** means a real CUDA GPU and a compatible CUDA build; **HIP** requires an AMD/HIP system and cannot validate its device implementation on the stated NVIDIA card. Some shared CUDA fixtures have separately named HIP targets.
- Skip code **77** is used for many unavailable GPU/ISA/architecture paths, where CMake marks it as a skip. Not every executable checks for a missing GPU, and a skip is not validation. In particular sm_80/sm_90 warp-specialized/shared-memory paths can skip on sm_120; do not infer coverage from “Blackwell” alone.
