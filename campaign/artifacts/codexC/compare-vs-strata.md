**Conclusion:** llama.cpp already supplies router/top-k, indexed expert kernels, heterogeneous tensor scheduling, selective expert uploads, and an optional LRU GPU expert cache. To reproduce the requested Strata mechanism, the primary missing component is **per-routed-expert CPU/GPU partitioning with concurrent execution and correct combination**, plus residency policy/tooling and lifecycle controls. This is a source comparison of the named hit-hook/cache model; Strata also has newer verify-window, prefill and model-family paths. It is not a claim that every Strata invocation uses `session_loop` or the same cache policy.

## Minimal build sequence

1. **Measure routing first.** Use an out-of-tree cb_eval harness against an ABI-matched existing library. Teacher-force a fixed token corpus and produce complete per-layer/token IDs plus optional weights. Make model/tokenizer identity, output-row settings, microbatch boundaries and resets explicit. This is the cheapest reusable research tool.
2. **Build a policy simulator.** Replay logical `(layer,expert)` IDs with quantized slice byte sizes. Compare existing llama LRU groups with fixed global/per-layer frequency allocations and decayed-use replacement. Split training and evaluation by prompt/conversation; report expert-hit rate, all-K-resident layer-hit rate, transfer bytes and CPU miss work separately. Llama cache counts unique experts per microbatch; Strata hook counters can count routed occurrences. Recompute a common metric before comparing percentages.
3. **Use existing cache as a residency baseline.** Sweep eligible host weights, cache bytes and microbatch sizes, including 1, 8, 32 and 33 tokens and the capacity guard. Recreate context for cold-cache trials. Capture actual assignment and cache aggregates; a nominal CPU-placement flag is not execution proof.
4. **Implement the missing seam in a prototype.** Route once, publish current activation/IDs, take a stable residency snapshot, launch resident expert GPU work, run CPU miss jobs, copy miss outputs and combine on the correct stream. Start with explicit synchronization as a correctness baseline before optimizing notification/capture.
5. **Gate optimization on numerical proof.** Compare each expert contribution and per-layer residual to a reference at identical input tokens; add all-hit, all-miss, mixed-hit, repeated-ID-across-tokens, changing-layer, eviction-in-flight and reset cases. GPU/CPU activation quantization and current-layer buffer reuse need dedicated fixtures.
6. **Measure overlap and adaptivity independently.** Keep numerical inputs fixed for overlap-on/off; use CPU+GPU timelines. Only then add profile preload, asynchronous replacements with publication-after-copy, and eventually KV/expert memory lending. Report uninstrumented wall time separately from callback traces.

This sequence follows D003's methodology emphasis: build tools that can falsify a mechanism claim, then build the mechanism. Source comments describing historical measured numbers are evidence of test intent, not measurements reproduced by this assignment.
