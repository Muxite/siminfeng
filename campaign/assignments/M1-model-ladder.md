## Deliverables
1. cc/ladder/ladder.py with subcommands, each a single bounded on-device step that the lead submits as a jobq gpu job:
   - `fit MODEL_ID`: try an ordered list of placement configs from the spec until one runs a 32-token decode without watchdog trip; record MemAvailable min, swap, load s, ms/token per config tried (stop at first success unless --all). Default config ladder for a model that may fit: [-ngl 99 -fa on -c 4096 (mmap default)], [same + -ctk q8_0 -ctv q8_0], [-ngl 99 -lm mmap -c 4096], [-ngl N partial...]; for over-memory MoE: [-ngl 99 -lm mmap -cmoe -c 4096 + best expert env (frd16 + pregate K=8 ORDER=after MAX_INFLIGHT=4)], [same without env]. Pin -c always.
   - `speed MODEL_ID`: llama-completion with the chosen config, 3 fixed prompts (short chat-templated prompts in cc/ladder/prompts/, non-thinking where template supports it), -n 256, --temp 0 -s 1, 2 reps each, counterbalanced order; summaries via cc/abrun/run_summary.py; report median eval_ms_per_token, tok/s, prompt tok/s, decode-window NVMe GiB/token, J/token, gpu_util.
   - `acc MODEL_ID --set mmlu_pro_140`: cc/acc mcq.py via cc/acc/server.py with the same config; non-thinking (record the template kwargs used).
   - `kld MODEL_ID --ref REF_ID`: cc/acc/kld.py (only for same-tokenizer pairs; cap chunks so the base file <= 3 GB; base files under ~/models/campaign/kl/).
   - `report`: aggregate all ladder results into experiments/jetson/LADDER/REPORT.md + ladder.json: one row per (model,quant,config): size GiB, fits/over-memory, ms/token, tok/s tier (>=2, >=5, >=10), MCQ acc ± Wilson CI, KLD vs ref, published scores (from spec), J/token. Plus a text scatter (accuracy vs tok/s) and the Pareto frontier list.
