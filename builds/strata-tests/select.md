## Protection gaps under this CPU-only gate

- **Direct expert-cache mapping/residency:** no CPU-only protection found for the actual `ExpertCache` admission/allocation path. The exchange test verifies the separate host ownership mechanism; it cannot substitute for candidate 1's CUDA-backed cache assertions.
- **Authoritative router/top-k and once-only weighting:** no runnable CPU-only production-router or Qwen pool-to-`moe_combine` integration test found. The GPU candidates demonstrate relevant assertions, but extracting their host references or passing a device-unavailable skip would not validate the production path. The no-double-weight contract is at `include/strata/core/expert_source.hpp:15-17`.
- **Stale activation at a stable address / stale hit rows:** no direct CPU-only adapter regression found that overwrites the same `x_f` buffer across calls, alternates hit/miss rows, and checks fresh reference outputs. Production explicitly requantizes each call (`src/core/expert_source.cpp:4745-4747`), clears previous hit rows (`:5373-5377`), and forbids previous-layer `mixed` quantization reuse (`:5385-5393`). The selected expert arithmetic test quantizes its inputs before the comparisons; it does not exercise this adapter contract.
- **Current expert identity and `hit_hook` dispatch ordering:** host ownership/ring identity checks above are narrower than current-layer adapter IDs. The required sequence is `Launch -> pool -> H2D misses -> Combine -> post`, with current IDs provided to `Launch` (`include/strata/core/hit_hook.hpp:13-21`, `:30-39`; `src/core/expert_source.cpp:4749-4756`). No direct CPU-only regression for that sequence was found. CMake conditionally names `bench/micro/hit_cpu_order_parity.cu` (`CMakeLists.txt:2718-2720`), but that source is **absent at this checkout**; it is not an available test, and its declared build is CUDA-only anyway.

## Offline build feasibility

The selected subset has an offline route without modifying Strata. Top-level GPU options support OFF (`CMakeLists.txt:80-94`, `:431`); the runner also disables SYCL, gfx906 and split-engine paths. Crucially, **native experts default ON** (`:176`): leaving that default would enter `FetchContent_Populate` for llama.cpp when `STRATA_GGML_DIR` is empty (`:2050-2057`, `:2104-2116`). Set `STRATA_NATIVE_EXPERTS=OFF`; the five selected tests need neither downloaded ggml nor Catch2. The local `third_party/ggml` contains format support files, not a complete llama.cpp `ggml` CMake project, and `third_party/llama.cpp` is absent. Do not assume a vendored full dependency checkout.

`tests/CMakeLists.txt` is absent here. Its optional `add_subdirectory` is existence-guarded (`CMakeLists.txt:2887-2892`), so no extra suite or Catch2 is configured through it. Set `STRATA_BUILD_TESTS=ON` explicitly: the default depends on that absent file (`:162-171`). `FETCHCONTENT_FULLY_DISCONNECTED=ON` and Docker `--network none` add defense; disabling the fetch's feature gate is the actual dependency solution. No package install, submodule update, download, copied source tree, patch, or source-local generated file is needed by this recipe. Successful compilation remains unverified under the assignment's no-build restriction.

## Native-OFF library link blocker and standalone expert recipe

A source-level defect affects the stock CPU library when native experts are OFF: `src/kernels/cpu/expert_layout.cpp:402-419` unconditionally references `q2_0_gguf_rows_multi_avx1`, `q2_0_gguf_rows_multi_avx1_legacy`, and `act_quant_q8_1_avx1`. Their definitions live at `src/kernels/cpu/q2_avx1.cpp:217-254`, but CMake adds that source **only inside** `if(STRATA_NATIVE_EXPERTS)` (`CMakeLists.txt:2057`, `:2122-2125`). The base native-OFF library sources omit it (`:1994-1999`). Linking the stock expert test is therefore expected to fail with unresolved symbols; this is a static finding, not an observed linker run. The three selected header-only CMake executables do not link this library.

The runner instead compiles these six unchanged sources to separate objects and links only those objects with `g++ -pthread`: `src/kernels/cpu/{expert_multi_test,expert,expert_layout,q2_avx2,q2_avx1,hadamard}.cpp`. Common flags are `-std=c++20 -O2 -UNDEBUG -pthread -I/src/include`; it defines no `STRATA_NATIVE_EXPERTS`, so the repository's own native-disabled implementations apply (`src/kernels/cpu/expert_layout.cpp:422-432`). No pool/engine object, CUDA runtime, or third-party library is linked.
